# Migrations

## ULID + composite tenant-safe FK extension for AR/AP
Top-level AR/AP master data and financial documents carry ulid CHAR(26) unique: customers, vendors, customer_invoices, customer_payments, customer_credit_notes, vendor_bills, vendor_payments, vendor_debit_notes. Skip ulid on addresses, lines, allocations, approval workflow tables, and audit_logs. Every org-scoped child carries organization_id plus a composite FK (organization_id, parent_id) REFERENCES parent(organization_id, id); parents have UNIQUE(organization_id, id).

## PH-specific tax schema
Tax tables are Philippines-specific. tax_codes.type is one of vat/withholding_tax/percentage_tax/excise/zero_rated/exempt and jurisdiction defaults to 'PH'; tax_rates.rate_type is standard/zero_rated/exempt/preferential with rate in [0,100]. tax_rates relies on the btree_gist exclusion constraint ex_tax_rates_no_overlap (daterange [from,to)) so effective intervals never overlap per §0.14. tax_rates and tax_codes carry UNIQUE(organization_id, id) so tax_transactions/lines can use composite tenant-safe FKs.

## Run migrations on pgsql_direct (non-pooled Neon) connection
Laravel's migrate wraps each migration in a transaction. The default `pgsql` connection uses the Neon pooled host (DB_HOST with `-pooler`), which fails DDL inside a transaction ("current transaction is aborted"). Always run `php artisan migrate --database=pgsql_direct` (host = DB_HOST_DIRECT, the non-pooled endpoint already wired in config/database.php). Keep the app on the pooled `pgsql` connection for web requests.

## PostgreSQL truncates constraint names to 63 chars — avoid collisions
Long composite constraint names auto-generated by Laravel truncate to 63 chars in PostgreSQL. Two different constraints on the same table can truncate to the SAME name and fail with "constraint already exists". E.g. `recurring_journal_executions_organization_id_recurring_journal_id_scheduled_run_date_unique` and `..._recurring_journal_id_foreign` both collapsed to `..._recurring_journal_`. Give explicit short names (uq_/fk_ prefixes, as in recurring_journal_executions) to any composite unique + foreign combination whose column prefix is long.

## Neon pooled connection: multi-statement transactions with DDL abort
DB is Neon via PgBouncer (host ends in `-pooler`). A DDL statement run through a PREPARED query inside one explicit transaction aborts that transaction; the next statement (even a SELECT) fails with 25P02 "current transaction is aborted". Single DDL per transaction (and autocommit DDL) are fine. For multi-statement ALTER migrations, set `public $withinTransaction = false;` on the migration so each statement autocommits. Caveat: a mid-migration failure then leaves partial state with no rollback, so order statements so dependencies precede use. The laravel-boost database-query tool can also get wedged into an aborted-transaction state for the whole session.

## Explicit short names for composite constraints
Auto-generated constraint names concatenate table + all columns (e.g. `reconciliation_matches_organization_id_journal_entry_line_id_foreign`) and can exceed Postgres' 63-char limit, getting silently truncated. A later `dropForeign(['a','b'])` recomputes the untruncated name and FAILS. Always pass explicit names (`fk_*`, `uq_*`) shorter than 63 chars when adding composite FKs or multi-column uniques to tables with long names.

## Migrations default to restrictOnDelete and use DB::statement for CHECK constraints
Foreign keys use `restrictOnDelete()` as the default deletion behavior. CHECK constraints are added via `DB::statement('ALTER TABLE ... ADD CONSTRAINT ...')` after the Schema closure, not inside the Blueprint.
